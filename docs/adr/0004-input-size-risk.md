# ADR-0004. Отказ от гарантии обработки чрезмерного входа на текущем этапе

- Дата: 13.11.2026.
- Статус: Принято.

## Контекст и ограничения

Карта К7 проверяет вход, превышающий обычный в 1000 раз. В [OpenAPI](../api/openapi.yaml) из PR №18 поле `BookingInput.topic` не имеет `maxLength`, `Idempotency-Key` не имеет верхней границы длины, а `GET /bookings` задаёт для `limit` только минимум. Общая граница HTTP-тела и ответ `413` отсутствуют.

Таким образом, существующий контракт не гарантирует контролируемый отказ на слишком большой корректный запрос. Нельзя заявить, что сервис уже возвращает `413` или `422` только из-за размера.

## Решение

**Сознательно не закрывать К7 защитой от чрезмерного размера в объёме текущей учебной версии.** Сохранить существующие схемы без вымышленных лимитов; явно зафиксировать границу гарантии и риск в этом ADR.

Для запроса обычного размера сохраняются все проверки типов, полей, времени и доступа. Корректный запрос, увеличенный в 1000 раз, не обязан отклоняться только из-за размера: он может пройти, если хватает ресурсов. Для чрезмерного входа не гарантируются определённый HTTP-код, JSON-тело ошибки, время ответа и отсутствие обрыва соединения. Клиент при неизвестном результате создания повторяет исходный запрос с прежним ключом по [ADR-0001](0001-persistent-idempotency.md), когда сервис снова доступен.

Это ограничение контракта, а не подтверждение успешной защиты. Причина выбора — учебный прототип внутри организации, отсутствие согласованного профиля нагрузки и назначенного владельца инфраструктурных лимитов; ввод численных ограничений требует согласования с владельцем API из PR №18. Решение недопустимо переносить на публичное промышленное размещение без пересмотра.

## Рассмотренные альтернативы

| Альтернатива | Оценка |
|---|---|
| Ограничить тело, длины строк и размер страницы в OpenAPI и входном слое | Предпочтительно перед реальным размещением, но требует отдельного согласования значений, формата `413` и поведения до парсинга JSON. |
| Ограничить только reverse proxy | Может защитить тело запроса, но не ограничивает `limit` и не гарантирует единый формат ошибки. |
| Полагаться только на типы и обязательные поля | Не ограничивает потребление ресурсов; защитой не считается. |

## Цена решения

Принят риск исчерпания памяти, долгого выполнения, чрезмерных ответов и отказа сервиса. У клиента нет гарантированного ответа на сверхбольшой вход. Проверка колодой должна отмечать К7 как сознательно не закрытую, а не успешно отражённую техническими средствами.

## Условия пересмотра

Пересмотреть до публичного или промышленного запуска, при согласовании нагрузочного профиля либо первом отказе из-за размера. Для закрытия карты определить лимиты тела, `topic`, ключа и страницы, место их проверки, единый ответ `413` и проверки граничных значений. До пересмотра гарантия защиты не заявляется.
