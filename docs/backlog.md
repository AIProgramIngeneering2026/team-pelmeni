## Задачи
### Issue 1. С1. Создание брони и проверка пересечений
Исполнитель:
Описание: реализовать POST /bookings — валидация интервала, проверка статуса комнаты, проверка пересечений, создание брони в статусе PENDING_CONFIRMATION, подтверждение → CONFIRMED.
Критерии приёмки: критерии сценария С1.

### Issue 2. С2. Отмена брони
Исполнитель:
Описание: реализовать DELETE /bookings/{id} — проверка, что встреча не началась, переход CONFIRMED → CANCELLED.
Критерии приёмки: критерии сценария С2.

### Issue 3. С3. Перенос брони
Исполнитель:
Описание: реализовать PATCH /bookings/{id} — проверка пересечений на новом интервале, обновление брони без смены статуса.
Критерии приёмки: критерии сценария С3.

### Issue 4. С4. Список своих броней
Исполнитель:
Описание: реализовать GET /bookings — только свои брони, сортировка по времени начала, фильтры по статусу и периоду, пагинация.
Критерии приёмки: критерии сценария С4.

### Issue 5. С5. Защита от двойной брони
Исполнитель:
Описание: уникальное ограничение по комнате и интервалу + транзакция; ответ 409 с идентификатором конфликтующей брони.
Критерии приёмки: критерии сценария С5.

### Issue 6. С6. Валидация некорректного времени
Исполнитель: 
Описание: проверка конца раньше начала, нулевой длительности, начала в прошлом; ответ 422 с понятным сообщением.
Критерии приёмки: критерии сценария С6.

### Issue 7. Уведомления через лог
Исполнитель: 
Описание: таблица notifications, адаптер LogNotifier, запись уведомления при создании, отмене и переносе брони, строка в лог при доставке.
Критерии приёмки: в notifications есть запись при каждой операции; в логе строка notification sent с типом и идентификатором брони.

### Issue 8. CI, миграции и health-check
Исполнитель: 
Описание: тесты в CI (можно с архивом алюр), миграции БД, эндпоинт health-check, единый формат ошибок 409 и 422 (ошибки из сценариев обязательные, можно добавить другие).
Критерии приёмки: CI зелёный на пустом PR; миграции накатываются с нуля; GET /health возвращает 200.
