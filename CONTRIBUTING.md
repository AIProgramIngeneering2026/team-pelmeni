# Как мы работаем

## Ветки
Имя ветки: тип/номер-задачи-краткое-описание.
Типы:
- feat — новая функциональность
- fix — исправление ошибки
- docs — документация
- infra — CI, миграции, окружение
- test — тестирование
- refactor — изменения, не влияющие на логику
Правила:
- В main пушим только через pull request, прямой push закрыт.
- Ветка живёт не дольше одной задачи.
- Перед PR делаем rebase на актуальный main.

## Коммиты
Формат: тип(область): краткое описание на русском языке.
Типы: feat, fix, docs, test, infra, refactor.
Правила:
- Тело — по желанию.
- Один коммит — одно логическое изменение.

## Pull request
Что должно быть в PR:
- Заголовок в формате коммита.
- Ссылка на issue.
- Краткое описание: что сделано и как проверять.
Правила:
- Минимум один review от другого участника.
- Merge только после approve и зелёного CI.
- Merge через squash, ветка удаляется после вливания(?).

## Review
Кто делает: любой участник команды, кроме автора PR. Автор не мержит
свой PR без чужого approve.
Как делаем:
- Смотрим diff целиком, а не только последний коммит.
- Проверяем соответствие критериям приёмки из issue.
- Оставляем замечания с указанием строки и предложением.
Что делает автор:
- Отвечает на каждый комментарий: исправил или объяснил, почему нет.
- После правок просит повторный review.
- Не резолвит комментарии ревьюера сам.

## Definition of Done

Задача считается выполненной, когда соблюдены все применимые условия:
- Выполнены требования и критерии приёмки из связанного issue.
- Результат проверен. Для изменений логики добавлены или обновлены тесты, включая ошибочные сценарии, предусмотренные задачей.
- Все автоматические проверки CI прошли успешно.
- Документация и контракты обновлены, если изменения затрагивают описанное в них поведение.
- Для задач по документации проверены содержание, ссылки и отображение Markdown, таблиц и диаграмм.
- Pull request содержит ссылку на issue, описание изменений и способ проверки.
- Получен минимум один approve от другого участника команды. Замечания review устранены или согласованы с проверяющим.
- Pull request влит в main.
- Cвязанный issue закрыт после проверки выполнения критериев приёмки.

Если условие неприменимо к задаче, причина указана в описании PR. Например, для исправления опечатки достаточно проверки документа без добавления тестов.
